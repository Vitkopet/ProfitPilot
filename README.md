# ProfitPilot — AICH Acceleration Detector

Експериментальний LONG-only сканер спостереження, Python 3.10+, без сторонніх бібліотек.
Не виставляє ордери й не потребує ключів біржі.

## Запуск на GitHub

Actions → AICH Acceleration test → Run workflow. Після завершення відкрийте запуск:
у секції Artifacts завантажте acceleration-report. Файл latest.json містить перевірені
монети, умови, кандидатів LONG_WATCH та помилки. Червоний запуск означає помилку;
це не рівнозначно відсутності сигналів. Перший push також запускає перевірку.

## Що перевіряється

До 50 найліквідніших доступних spot USDT пар Binance з добовим обсягом від 5 млн USDT.
Використовуються лише закриті 5-хвилинні свічки. LONG_WATCH вимагає одночасно:

- зростання за 15 хв ≥ 0.6%; прискорення проти попередніх 15 хв ≥ 0.4 процентного пункту;
- обсяг за 15 хв ≥ 2 медіан попередніх неперекривних 15-хвилинних вікон;
- закриття вище максимуму попередніх 24 свічок;
- випередження BTC за 15 хв ≥ 0.3 процентного пункту;
- зростання за годину від 0 до 8%, спред ≤ 0.3% та достатня ліквідність.

Це початкові тестові пороги, не перевірена прибуткова стратегія. LONG_WATCH — кандидат
для спостереження, не рекомендація купувати. Немає підтвердження Kraken/деривативами,
перевірки R/R ≥ 1:4, входів, виходів, комісій, прослизання чи обліку PAPER-позицій.
Ці частини потрібні до повноцінного PAPER-тесту. Не реалізовано Viber і автоматичне
навчання. MICRO v1.1 не входить у пакет і не змінювався.

## Локально

```bash
python -m unittest -v
python acceleration.py --limit 50
```

Мережеві обмеження Binance або GitHub можуть спричинити помилки. Сканер повідомляє їх,
не підміняє дані й не обходить обмеження. Джерело: публічний data-api.binance.vision.
Розклад увімкнено: кожні 5 хвилин цілодобово (на хвилинах 02, 07, 12, …, 57 кожної години).
Звіти кожного запуску зберігаються в Artifacts протягом 7 днів. Ручний запуск також доступний.
GitHub Actions може затримувати запуски; це не постійний торговий сервер.

## План PAPER-перевірки

Після перевірки даних додати журнал кандидатів із незмінними часовими мітками,
Kraken-фільтр доступності, правила входу наступною свічкою, стоп/ціль, R/R ≥ 1:4,
комісії та прослизання. Зберігати стан між запусками, дедуплікувати сигнали,
консервативно обробляти свічки, де зачеплено і стоп, і ціль. Лише після цього
збирати 2–4 тижні PAPER-історії й порівнювати з базовою стратегією.
